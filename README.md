# Resume Builder

Локальный редактор резюме в духе novoresume.com. Слева форма, справа лист A4
в реальном времени; экспорт — через печать браузера, поэтому текст в PDF
остаётся векторным и читаемым для ATS-роботов.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
```

Прочие команды: `npm test` (vitest), `npm run typecheck`, `npm run lint`,
`npm run build`.

## Своё резюме против демонстрационного

В репозитории лежит обезличенное демо-резюме (`src/data/defaultResume.*.ts`) —
его видит любой, кто открыл проект впервые. Личных данных там нет и быть не
должно.

Настоящее резюме живёт в `public/resume.local.json`. Этот файл перечислен в
`.gitignore` и не уезжает в репозиторий: контакты, фото и история работы
остаются на твоей машине.

Порядок загрузки при старте (`src/lib/bootstrap.ts`):

1. правки в `localStorage` — они всегда важнее;
2. `public/resume.local.json`, если он есть;
3. демо-резюме.

Чтобы завести или обновить свой файл: отредактируй резюме, нажми
**«Экспорт JSON»** и сохрани скачанный файл как `public/resume.local.json`.
Кнопка **«Сбросить»** возвращает именно к нему, а к демо — только если файла нет.

## Как пользоваться

- **Правка.** Шапка и контакты — вверху панели. Секции ниже: заголовок правится
  прямо в карточке, «▼» разворачивает содержимое.
- **Порядок и колонки.** Карточки секций перетаскиваются за ручку слева, в том
  числе между «Левой» и «Правой» колонками. Внутри секции так же переставляются
  записи и отдельные строки достижений. Кнопка «👁» убирает секцию из резюме,
  не удаляя её.
- **Навыки.** Вводятся в поле внизу секции по Enter, чипы перетаскиваются,
  клик по чипу открывает его на редактирование.
- **Фото.** Загружается кнопкой в шапке и хранится внутри JSON как data-URL,
  поэтому файл резюме самодостаточен.
- **Разметка в тексте.** В любом текстовом поле работает `**жирный**` и
  `*курсив*` — этого хватает на академический формат вида
  «**GPA:** 4.4 / 5.0» и курсивной строки со специальностью. Разметка
  разбирается вручную и превращается в `<strong>` / `<em>`, HTML из полей
  ввода не исполняется.
- **Оформление секции.** В развёрнутой карточке: «Линейка под заголовком»,
  «Дата справа в строке» (период уходит вправо, на строку с названием — как в
  академических CV) и выбор маркеров списка: кружки, тире или без маркеров.
  Все три необязательны, по умолчанию секция выглядит как в исходном шаблоне.
- **Языки.** Переключатель `EN / RU` меняет редактируемый документ; версии
  независимы. «Скопировать из EN» переносит структуру и содержимое, чтобы
  переводить поверх готового.
- **Границы страниц.** Над листом висит бейдж «Помещается на одну страницу»
  или «N страницы — за край первой уходит X мм», а по самому листу проходит
  пунктир с подписью «конец страницы». Без этого лист выглядит бесконечным, и
  переезд на второй лист обнаруживался только в готовом PDF.
- **PDF.** Кнопка «Скачать PDF» открывает печать браузера — выбрать
  «Сохранить как PDF» и поля «Нет». Галочка «Фоновая графика» роли не играет:
  лист печатается с `print-color-adjust: exact`, поэтому тёмная полоса
  контактов и подложки чипов попадают в PDF в любом случае.

Текущее состояние автосохраняется в `localStorage`. Это черновик, а не
хранилище: чистка данных сайта его сотрёт, поэтому важные версии выгружай в JSON.

## Устройство

```
src/
  types/resume.ts          модель: документ — плоский список секций
  store/useResumeStore.ts  zustand + immer + persist, все правки идут сюда
  data/                    демо-резюме (EN) и его пустой каркас (RU)
  lib/bootstrap.ts         выбор источника данных при старте
  lib/io.ts                экспорт, импорт, валидация файла
  templates/novo/          вёрстка листа и print-стили
  components/editor/       формы, drag-n-drop, тулбар
  components/preview/      масштабирование листа под ширину окна
```

Секция описывается типом (`experience`, `projects`, `education`, `skills`,
`text`), колонкой и флагом видимости, поэтому новый блок добавляется без правок
шаблона — через кнопки «Добавить секцию».

Счётчик страниц меряет высоту содержимого, а не самого листа: на экране лист
растянут `min-height` до 297 мм, а при печати это правило снято, и считать по
нему значило бы всегда получать лишнюю страницу.

У блока с колонками намеренно нет нижнего внутреннего отступа. Padding в конце
потока применяется один раз, в самом низу документа: нижним полем первой
страницы он не становится, зато способен вытолкнуть за край пустую вторую
страницу.

## Требования к Node

Нужен Node `^20.19.0 || >=22.12.0` — это требование vite 8, rolldown и oxlint;
оно записано в `engines`, и хостинги вроде Vercel читают его при сборке.

На более старой версии (например 22.11) npm молча пропускает нативные бинарники
rolldown и oxlint: они объявлены как optional-зависимости с тем же `engines`, а
неподходящие optional-пакеты npm пропускает без ошибки. Внешне это выглядит как
поломка `vite build`, `vitest` и `oxlint` с «Cannot find native binding».
Лечится обновлением Node:

```bash
nvm install 22.20.0 && nvm use 22.20.0
rm -rf node_modules package-lock.json && npm install
```

Как разовый обходной путь на старой ноде можно доставить бинарники под свою
платформу, не трогая манифест и lock-файл:

```bash
npm install --no-save --no-package-lock   @rolldown/binding-win32-x64-msvc @oxlint/binding-win32-x64-msvc
```

В `package.json` их прописывать нельзя: пакеты объявляют `os: win32`, и на
Linux-сборщике установка упадёт с `EBADPLATFORM`.

## Деплой

Статическая сборка, сервер не нужен.

1. `npm run build` — результат в `dist/`.
2. На Vercel: framework preset **Vite**, build command `npm run build`,
   output directory `dist`. Netlify и GitHub Pages подойдут так же.

Личное резюме на задеплоенный сайт не попадает: `public/resume.local.json`
исключается из сборки плагином `exclude-local-resume` в `vite.config.ts`.
На опубликованном сайте открывается демо-резюме, а правки посетителя остаются
в localStorage его браузера.
